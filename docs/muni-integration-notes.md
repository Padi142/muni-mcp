# MUNI integration notes for a personal TypeScript MCP

Research date: 1 November 2026. This companion note uses only public, official MUNI documentation, including search-indexed help pages where direct retrieval returned no readable content. No credentials, authenticated access, or API calls were used. Documented capabilities are distinguished below from proposed discovery work; this is not an implementation or an endpoint availability test.

## Verified facts

**IS MU is the central study and teaching system.** MUNI describes it as supporting study administration, e-learning, and university communication. Its student help covers course registration/enrolment, seminar groups, examinations and assessment, study materials, and study planning. These are distinct areas with potentially different access requirements, rather than evidence of one student API. [IS MU service description](https://it.muni.cz/sluzby/informacni-system-mu), [IS MU help index](https://is.muni.cz/napoveda/?id=301442).

**Public course information is a useful initial surface.** The catalogue supports searches by code, name, teacher, faculty, and teaching period, with reusable query URLs. A public PB161 listing demonstrates course descriptions and learning outcomes; its permalink includes faculty, semester, and course code. A course must therefore be identified in its teaching context, not just by its display name. [Catalogue search help](https://is.muni.cz/napoveda/predmety/katalog_vyhledavani), [PB161, spring 2026](https://is.muni.cz/course/fi/spring2026/PB161?lang=cs).

**IS MU has its own e-learning tools.** Interactive syllabi organize materials and activities, including questionnaires, file submission areas, and communication tools. Teachers can also use these tools without an interactive syllabus. Student views expose materials, submission areas, available questionnaires, and discussion activity. Consequently, “course content” need not be one file tree, and the presence of an IS course does not establish where every assignment lives. [Student syllabus help](https://is.muni.cz/napoveda/student/elearning), [E-learning overview](https://is.muni.cz/napoveda/elearning/elearning).

**Calendar export is documented.** IS MU distinguishes the semester timetable from a calendar containing timetable events, exams, and other dated activities. Calendar settings provide a subscription URL for external calendars; hidden layers are excluded from synchronization. MUNI also documents timetable export as an iCalendar `.ics` file. These are useful read-only inputs, but they do not establish that every assignment deadline is exported. [Calendar help](https://is.muni.cz/napoveda/komunikace/kalendar?zoomy_is=1), [Official iCalendar export announcement](https://is.muni.cz/blog/is_info/nov_20131008_kalendar).

**Public API documentation exists, with important boundaries.**

- The File Manager API returns UTF-8 XML metadata for files and folders, respects node-level read permissions, and downloads file contents separately through file URLs. Its examples concern the Document Server and recommend a non-personal account for repeated automation. Support for the desired teaching-material locations must be checked. [File Manager API](https://is.muni.cz/napoveda/technicka/spravce_souboru_api).
- Non-personal accounts act under their owner's identity and permissions. Creating one requires the `w_neosobni` right; ordinary student access cannot be presumed. [Non-personal account help, on a MUNI-hosted IS help mirror](https://autoconfig.mail.muni.cz/napoveda/technicka/neosobni_ucet?lang=en%3Bid%3D307628%3Bks%3Dconversion).
- The notebook API documents XML operations for course information, enrolment lists, and notebooks, including writes. Keys are created through the Teacher area for one course and period, require an expiry and allowed IP addresses, and must be enabled. This is not evidence of a personal student token covering all courses or grades. [Notebook API help](https://is.muni.cz/napoveda/technicka/bloky_api?lang=cs%2F%3Bzoomy_is%3D1).

**Authentication is not a data-access contract.** IS MU documents UČO/primary-password login and distinguishes primary from secondary passwords. MUNI SSO supports OIDC and SAML2 for connected services and documents an approval step. Those identity protocols do not establish authorization to retrieve private IS study data. [IS access help](https://is.muni.cz/help/jine/pristup), [SSO integration documentation](https://it.muni.cz/sluzby/jednotne-prihlaseni-na-muni/informace-pro-spravce-webovych-serveru).

**Faculty teaching systems are separate.** ELF is the Faculty of Arts' Moodle-based service, with enrolment integration from IS MU; its documented automatic enrolment covers selected faculties. The Faculty of Education separately offers Moodlinka, also based on Moodle. Shared university identity or enrolment integration does not establish a shared API or a universally available Moodle web-service token. [ELF service](https://it.muni.cz/sluzby/phil/elektronicke-kurzy), [Moodlinka service](https://it.muni.cz/sluzby/ped/moodle).

## Proposals and unknowns: first discovery steps

1. Define the student's faculty, teaching period, and a small representative course set. Record which resources live in IS MU, ELF, Moodlinka, or another course site. Keep these as separate prospective connectors.
2. Prioritize public catalogue lookup and user-supplied `.ics` import. Later investigate a user-provided subscription URL, treating it as potentially sensitive. Check recurrence, timezone, exceptions, refresh behavior, and enabled calendar layers before promising schedule completeness.
3. Investigate which read-only mechanism an ordinary student can use for their enrolments, assessments, materials, and deadlines. Check exports, authenticated page structure, session behavior, and documented automation limits. Public documentation reviewed here does not establish a general student REST API or OAuth study-data scopes; IS support is a possible source for unresolved access questions. [IS access help](https://is.muni.cz/help/jine/pristup).
4. Ask each relevant faculty service whether student web-service tokens and the required read functions are enabled. Leave private grades, submissions, and comprehensive deadlines uncommitted until a supported access path is established. For TypeScript planning, preserve source URLs, source-system identity, and faculty/period/course identifiers in the eventual data model.
